# 工作站待验收事项

当前部署见[工作站指南](../deployment/workstation.md)，已通过的服务行为见 [API 契约](../api.md)与指南里的实测记录。

## 后续验收

1. **浏览器实物交互**：通过 localhost SSH 隧道验证麦克风、屏幕、实际扬声器播放、静默、插话和恢复。记录设备、浏览器及交互结果。
2. **可信 HTTPS**：由 tailnet 管理员启用 Serve，配置私网 HTTPS，验证浏览器权限与原生语音 WebSocket 连接。
3. **完整 262K 窗口**：构造接近单请求上限的多轮历史，记录输入／输出预算、早期事实检索、首增量、显存及取消释放。长短请求混跑继续按总 token 预算准入；多路满窗口作为独立容量评估，结合量化、模型与硬件分工测量。
4. **默认 CoT 长历史质量**：以当前默认策略复验 Omni 约 8K 和后台长历史，分别记录思考与正文、完整答案及历史保留。
5. **持续负载**：按应用确定的请求长度、调用强度和通话时长评估 QoS；当前功能验收周期约半小时。

外部 Swarm／orchestrator 通过 Responses provider 接入，应用项目持有各 worker 的历史分支与工具循环。

## 替换角色配图模型

当前基线是 FLUX.2-klein-4B、BF16、4 个去噪步、guidance 1.0 和 1024×1024 输出。常规版角色在匹配的抬膝、长椅和走路场景里出现腿尾粘连、多余尾部和鞋子长在尾端等问题。增加解剖和服饰描述能改变部分特征，6、8 步仍会重现结构错误。图库选图可以独立使用。候选权重和生产切换尚未确定。

1. 在隔离的图像 worker 上接入候选模型，沿用现有[图片作业 API](../api.md#生图任务)。检验原始参考图实际进入图像条件，任务返回真实模型版本、seed 和 PNG，并能取消、排队及恢复。模型加载、采样与显存安排由服务承担。
2. 用号主批准的常规版和 Q 版设定稿分别画抬膝、坐长椅和海边拿地图行走。先用相同场景与基线 seed 29873 比较，再换 seed 和场景复验。保存整批结果，包括失败图。使用候选模型适合的采样设置，记录每张的实际参数。
3. 逐图看两腿两鞋是否能分别沿轮廓辨认，单一鲸尾是否从骨盆后方接出，尾端是否保持水平双叶。服饰对照鳍耳、发箍与发结、领口宝石、鲸纹围裙、金色裙边和白色蕾丝。另查 Q 版头身比、短袜与圆头鞋，以及常规版的长身比例和带跟搭扣鞋。将遮挡和实际画错分别记录。
4. 在工作站同一 GPU 分工下测纯推理、排队至可下载总耗时、峰值显存与后台 Responses 恢复，复核并发通话体验。把两套形象的同场对照交给号主查看，再决定采用哪套及是否切换。私有原稿、成图与应用凭据保存在工作站或号主的验收目录。
